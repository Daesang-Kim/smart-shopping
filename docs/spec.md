# 농수산물 가격 판단 앱 — 개발 스펙 (KAMIS Open API 공모전 출품작)

## 1. 문제 정의
소비자가 마트/정육점에서 농수산물을 살 때 "지금 이 가격이 싼 건지 비싼 건지" 판단할 근거가 없다.
- 급하지 않으면 기다렸다가 사고 싶고, 급하면 지금 사더라도 "잘 산 건지"는 알고 싶다.
- 도매가보다 **소매가**가 실제 소비자 체감에 더 맞는다.
- 품목마다 "어떤 요일이 저렴한지" 같은 패턴도 궁금해한다.

## 2. 핵심 사용자 흐름
1. 앱 진입 → 상단 **검색창 + 카메라 버튼**
   - 텍스트로 품목 검색 (예: "삼겹살")
   - 또는 카메라로 **가격표 촬영 → OCR로 품목명/가격 자동 인식**
2. 인식/검색된 품목의 **상세 화면**으로 이동 (아래 3번 항목)

## 3. 상세 화면 구성 (핵심 기능 명세)

### 3.1 오늘 가격 + 판단 배지
- 큰 숫자로 오늘 소매가 표시
- 배지 1: **최근 90일 가격 분포 중 오늘 가격의 위치** (예: "상위 22% · 비싼 편")
  - 계산: 최근 90일 소매가 리스트에서 오늘 가격의 백분위 순위
- 배지 2: **작년 같은 날짜 대비 등락률** (예: "작년 이맘때보다 +8%")

### 3.2 가격대 게이지
- 최근 90일 최저가~최고가 범위를 막대로 표시, 오늘 가격 위치를 마커로 표시

### 3.3 가격 추이 그래프 (핵심, 스와이프 가능)
- 가로 스크롤로 더 긴 기간(과거~향후 몇 주)을 볼 수 있어야 함
- **올해 라인(실선)**: 오늘까지의 실측 데이터만 표시, 미래는 그리지 않음
- **작년 동기간 라인(점선/고스트)**: 작년 데이터는 이미 다 있으므로 "오늘에 해당하는 날짜" 이후까지도 계속 그려서, 예년엔 이 시점 이후 가격이 어떻게 움직였는지 참고할 수 있게 함
- **명절/이벤트 마커**: 추석 등 음력 명절은 해마다 양력 날짜가 다르므로, 올해/작년 각각의 실제 날짜를 계산해서 마커를 찍어야 함 (하드코딩 금지)
  - 예시(검증됨): 2026년 추석 9월 25일(금), 2025년 추석 10월 6일(월) — 양력으로 11일 차이
  - 날짜 계산: 음력-양력 변환 라이브러리 또는 공공데이터포털 "특일 정보" API로 매년 조회
- 주말(토/일) 처리: **KAMIS는 토·일·공휴일 조사를 하지 않으므로 이 그래프에는 주말 구간을 별도 표시하지 않는다** (실측 평일 데이터만 연결)

### 3.4 요일별 평균가 막대그래프
- 최근 3개월 기준 월~일 7개 막대
- 월~금은 실측 평균값
- **토/일은 추정치**: 직전 금요일 평균값과 다음 월요일 평균값을 3등분하여 배분
  - 토 = 금 + (월−금) × 1/3
  - 일 = 금 + (월−금) × 2/3
- 추정 막대는 실측과 시각적으로 구분(빗금 패턴 등)하고 "추정" 라벨 표시, 하단에 "실제 조사값이 아님" 문구 필수
- 최저 평균가 요일을 하이라이트

### 3.5 최근 90일 최저가 콜아웃
- "최근 90일 최저가: OOO원 · O월 O일 (요일)" 형태로 표시

### 3.6 구매 타이밍 조언 문구
- 톤: **확정적 예측 아님**, "과거 패턴 참고용"으로만 서술
- 예: "예년엔 이맘때 이후 가격이 내려가는 경향이 있었어요. 참고용 정보이며 항상 그런 건 아니에요."
- 보관 가능 품목(마늘, 양파 등)과 신선채소(잎채소 등)에 따라 추천 강도를 다르게 주는 것도 고려

### 3.7 하단 각주 (항상 표시)
- "KAMIS 소매가격 기준 · 주말·공휴일은 조사하지 않아 추이·요일 비교에서 제외/추정 처리됨"

## 4. 품목 인식 (검색/OCR)

### 4.1 텍스트 검색
- KAMIS 품목 코드표(API #15: 농축수산물 품목 및 등급 코드표) 기반 자동완성

### 4.2 가격표 촬영 → OCR
- **바코드 스캔은 채택하지 않음** — 정육점/마트 저울 라벨은 표준 바코드(GS1)가 아닌 매장 내부코드(PLU)라 매핑 불가하고, 표준 바코드 매핑 DB(GS1코리아 코리안넷)는 개인 프로젝트로 접근하기 어려움
- 대신 라벨의 **한글 텍스트를 OCR로 인식**하는 방식으로 결정
  - 후보 라이브러리: Google ML Kit Text Recognition(온디바이스, 무료) 또는 네이버 Clova OCR(정확도 우선 시)
- OCR 결과 텍스트를 KAMIS 품목명 리스트와 **유사도 매칭**(자모 단위 편집거리 등)해서 후보 2~3개 제시 → 사용자가 탭해서 확정 (완전 자동 인식 실패 시에도 UX가 자연스럽게 이어지도록)

## 5. 데이터 소스 — KAMIS Open API

| 용도 | API |
|---|---|
| 핵심: 기간별 소매가격 (최대 1년) | #17 (신) 일별 품목별 소매 가격자료 |
| 최근 시세 요약 | #6 최근일자 도소매가격정보(상품 기준), #7 최근 가격추이 조회 |
| 전년 비교 보조 | #4 연도별 도소매가격정보 |
| 품목/등급 코드 매핑 | #15 농축수산물 품목 및 등급 코드표 |

- 신청 절차: 회원가입 → 사용신청 → 키 발급 (공공데이터포털 경유 시 승인 대기 없이 즉시 이용 가능)
- **주의**: 축산물(삼겹살 등)은 일부 API에서 "축평원 데이터 제외" 단서가 있어, 실제 구현 전 해당 품목이 API #17에 포함되는지 먼저 확인 필요. 없을 경우 축산물품질평가원 Open API 별도 연동 검토

## 6. 기타 기술 스택 메모
- 명절/공휴일 날짜: 공공데이터포털 "특일 정보" API 또는 음력 변환 라이브러리로 매년 자동 계산 (하드코딩 금지)
- 프론트엔드 참고 목업: `price-check-mockup.html` (별도 첨부) — 색상 토큰, 레이아웃, 배지/게이지/차트 스타일 참고용. 실제 구현체는 이 스펙에 따라 자유롭게 프레임워크 선택 가능

## 7. MVP 범위 제안
- 품목 3~5개(기후/명절 민감 품목: 배추, 양파, 대파, 삼겹살 등)로 축소해서 시작
- 1차: 검색 기반 품목 조회 + 가격 판단 배지 + 추이 그래프
- 2차: OCR 인식, 명절 마커, 요일별 평균가, 전년 비교
